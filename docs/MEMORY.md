# Amadeus 智能记忆

## 参考项目与取舍

2026-09-06 查阅项目官方仓库和文档，借鉴机制，自行实现应用需要的部分。

| 项目 | 参考点 | 本应用实现 |
| --- | --- | --- |
| [Mem0](https://github.com/mem0ai/mem0) | 事实提取、实体与多信号检索；当前 README 的新版算法为追加记录 | 提取主题与标签，结合主题、文字和新近程度选候选，保留更正前后的记录 |
| [Memobase](https://github.com/memodb-io/memobase) | 用户资料与事件时间线、在回复路径外批量整理 | 对话完成后后台提取，按资料、事件、关系和剧情分类 |
| [Letta](https://docs.letta.com/v1-sdk/concepts/stateful-agents) | 持久记忆与对话状态的分层管理 | 重要资料与检索到的旧记忆组合进入上下文，原始记录独立保留 |
| [Hindsight](https://github.com/vectorize-io/hindsight) | 提取事实、时间和关系，结合多种检索信号 | 记忆携带原话证据与来源时间，区分当前事实和被更正的历史版本 |

没有接入上述项目的托管存储或 SDK。存储继续使用本设备 JSON / localStorage；语义检索由用户当前聊天模型选择候选记录，不使用向量数据库。

## 保存与更新

- 自动记忆始终启用。对话完成后保存用户原话、已清理回复与时间作为待处理来源；这些原始片段仅用于事实提取，不直接作为长期记忆参与检索。旧数据继续保留，但不再从聊天记录自动导入旧式记忆。
- 完成回复后自动分批处理未整理来源，每批最多 6 段，优先最新内容，继续处理剩余批次。无需手动操作。整理使用当前聊天协议、地址、模型与本次内存中的 API Key，额外消耗模型请求。新消息、挂断、删除记忆或保存设置会取消当前整理，未完成的批次在后续成功对话后继续处理。
- 提取记录标记 `source=learned`，包含 `key`、`text`、`tags`、`time`、`evidence`。`scope=user` 是现实资料，`scope=roleplay` 是虚构身份和剧情；`kind` 分为 `profile`、`event`、`relationship`、`scene`。
- 模型只能引用本批用户原话作为证据；服务端检查引用确实出现在原文、更新目标存在且属于同一范围。助手回复仅用于理解指代，不能单独证明用户事实。引用检查不能保证模型的语义判断一定正确，用户可查看依据并删除错误记录。
- 明确更正生成新事实，旧事实保留并标记 `supersededBy`；较早资料不能替换时间更晚的当前事实。相同范围、相同文本不会重复新增。手动记忆不会被模型自动修改。
- 每段整理输入最多包含用户原话前 6000 字符、回复前 3000 字符。原话全文继续保留，不宣称已理解被截去的部分。
- 清空对话与清空记忆相互独立。记忆页仅显示已保存的事实及以前手动保存的内容，支持逐条删除与清空；清空也会删除待处理来源。删除与整理并发时不会把已删除内容重新写回。旧的关闭开关、手动添加、手动整理、分类和搜索入口已移除。

## 回忆与上下文

近期上下文保留最多 12 条消息，通常不超过 16000 字符。结构化事实、主题标签与新近程度用于本地候选排序；原始对话来源不直接进入长期记忆检索。以前保存的手动记忆继续保留、可查看删除和正常检索，不再享有单独置顶规则。

语义回忆自动运行：候选记忆超过 8 条时，将最多 80 条候选的简短描述与最近话题发给当前模型，选择最多 8 个相关 ID。这能识别同义表达与上下文联系，但会在回复前增加一次模型请求。候选描述最多 400 字符，因此超大记忆库和长记录存在召回限制。候选不超过 8 条时直接组装上下文。

最终上下文合并最多 2 条相关的稳定资料/关系/场景与检索结果，总计最多 8 条、6000 字符。发送给聊天模型的事实注明范围、类别、来源时间与当前/历史状态；旧事实不能当成当前状态，虚构场景不能当成现实履历。

整理或检索出错会显示错误，不自动重试或编造成功。整理失败不影响已完成的聊天，未处理来源继续保留；检索失败时本次请求显示错误。

## 代码入口

- `src/memory.js`：事实合并、候选排序、删除与上下文组装。
- `src/useMemory.js`：后台整理、语义检索和取消。
- `server/memory.mjs`：`POST /api/memory` 的 `extract` / `recall`、模型提示词和结果校验。
- `src/Settings.jsx`：自动状态、查看记忆与依据、逐条删除与清空。

记忆始终归当前设备所有。电脑服务只处理本次请求，不建立服务端用户记忆库；本次需要整理或检索的文本会发给所选模型服务。Codex 接入继续使用禁用工具、MCP、宿主记忆的独立临时会话，记忆任务使用单独的 JSON 输出指令。
