# Amadeus 智能记忆

记忆由三层组成：设备保存的完整来源、带依据的细粒度事实、回答时组合的用户资料与相关经历。目标是记住具体的人、事、原因和约束，并随用户更正更新。

Memobase 的用户资料与事件分层是主要组织方式。Mem0 当前主分支写入以追加和去重为主；本应用的显式更正策略主要借鉴 Memobase 的新增／更新区分，再保留历史版本。Hindsight 的完整方案使用向量、图和时间索引；本应用采用其中的组合检索思想，使用本地关键词与实体索引、模型语义筛选。没有接入这些项目的托管存储、SDK、向量数据库或服务端用户记忆库。

这些机制与 ChatGPT 的后台记忆整理目标相近，不能据此宣称复现其内部架构或达到同等效果。[OpenAI 公开说明](https://openai.com/index/chatgpt-memory-dreaming/)

## 保存与细节提取

成功对话后立即保存用户原话、清理后的回复和时间，再由当前聊天模型在后台提取。助手回复只能辅助理解指代，不能成为用户事实的证据。

- 每条事实保留对象、原因、条件、数量、时间和结果。例如“22 点后不喝咖啡，因为喝拿铁会失眠”保留时间条件和原因，不会只缩成“饮品偏好”。
- 分类为 `profile` 个人资料、`preference` 偏好习惯、`goal` 目标进展、`event` 事件计划、`relationship` 关系约定、`scene` 剧情进度。`scope=user` 与 `scope=roleplay` 分开，剧情不得成为现实履历。
- 使用具体主题，例如“小林/生日”和“小林/饮食限制”。`entities` 记录明确的人名、项目名、设备名等，供关联检索使用。
- 每批最多 6 个来源片段、48 条事实，每条最多 600 字。长用户消息每次前进 6000 字符，后续片段保留 300 字符重叠；保存处理位置，直到全文处理完成。不会处理开头后就把整条长消息标成已完成。
- 最多带入 2 条相邻旧对话辅助消解指代。依赖旧对话的事实同时引用新旧用户原话；每条至少有一条本批原话，不能只根据旧上下文重新生成记忆。
- 单条包含 `key/text/scope/kind/tags/time/evidence`，可附 `entities/importance/state/eventDate`。重要度 1–3 区分普通经历、持续偏好、明确要求记住的事项，不代表真实性置信度。
- 记录时间 `time` 与事件日期 `eventDate` 分开；相对日期根据原话时间与设备时区理解。`state` 区分当前、计划、进行中、完成、过去；过期计划不能自动视为完成。

密码、令牌和 API Key 不应提取为记忆。保存设置与密钥是独立的设备配置功能，不进入记忆输入或对话导出。

## 补充、更正与删除

同主题不等于同一事实。新爱好、不同人物属性和不同事件分别保留，不能自动覆盖。

补充或更正通过 `supersedes` 指定被更新的自动记忆。新版本保留未改变的细节与新旧依据，旧版本保留并记录 `supersededBy`。较早的原话不能替换时间更晚的状态。相同事实再次确认会补充证据与提及时间，不重复堆积；每条最多保留 12 处去重依据。原始来源仍单独保存。

服务端核对原话是否逐字存在、引用是否包含本批来源、更新目标是否属于相同范围的自动记忆。校验不能完全证明语义推断正确，所以记忆页保留查看依据和删除入口。以前的手动记忆不会被模型自动改写。

删除与清空都会取消未完成的整理和检索。删除单条事实后，其来源不再作为待处理或指代上下文使用，避免长来源的后续片段再次生成已删除内容。已从同一来源得到的其他事实继续保留。清空记忆删除事实与待处理来源；清空对话独立进行，长期记忆仍保留。不会从聊天记录重新导入已删除记忆。

## 回忆与上下文

1. 本地 BM25 根据词频、词的区分度和记录长度寻找候选，中文／日文使用相邻双字分词。实体名称、重要度、重复证据与新近程度参与排序。
2. 按候选中的人物或项目补充关联事实，并保留重要资料候选。最多发送 160 条、每条 600 字的候选。
3. 超过 8 条候选时由当前聊天模型选择最多 16 条相关记录；指代、原因、偏好条件和项目进展共同参与判断。候选不超过 8 条时直接组装。
4. 回答上下文优先使用语义结果，再合并最多 6 条重要资料／偏好／目标／关系／场景、最多 4 条同范围的实体关联记录。总计最多 24 条，JSON 内容预算约 14000 字符；每条可带最多 2 处原话片段与时间。

最近上下文仍保留最多 12 条消息，通常不超过 16000 字符，最新单条长消息保留完整。原始来源不直接作为长期事实检索；回答使用事实及其证据。旧版本标明历史状态，模型应以当前更正为准，并在资料未包含某事时承认不知道。

## 运行边界

记忆全部归当前设备：Android 使用应用私有 JSON，网页使用当前浏览器存储。电脑后端只处理本次请求，相关文本会发送给用户所选模型。Codex 使用禁用工具、MCP、宿主记忆的独立临时会话，记忆任务使用专用 JSON 指令。

整理使用当前聊天协议、模型与已保存密钥，额外消耗模型请求。新消息、挂断、删除或设置变更取消任务；未完成来源在后续成功对话后继续处理。失败显示具体错误，不自动重试。语义检索会增加回复前的等待时间。

保留完整原话不等于模型逐项理解绝对无遗漏。单批事实数量、候选容量、模型判断和相邻上下文长度都有边界。极大记忆库中的间接关联、超过两条旧对话的模糊指代仍可能漏召回；本实现没有向量数据库，也未作大规模长期效果评测。

## 代码入口

- `src/memory.js`：分片、BM25、实体关联、合并、删除与上下文。
- `src/useMemory.js`：后台提取、语义回忆、取消。
- `server/memory.mjs`：模型提取／检索指令、来源与更新校验。
- `src/Settings.jsx`：自动状态、记忆依据、删除；旧版本默认折叠。
- `tests/smart-memory.test.mjs`：细节共存、更正、证据、长消息、关联回忆与删除行为。
